Lesson 02 · Foundations

先搞懂 LatentMoE 和 KDA

这次不要求你背 Kimi K3 的结构图。你只需要获得两个可复用的判断：MoE 解决“参数容量和计算量”的矛盾，KDA 解决“长历史和 Attention 成本”的矛盾。

第一层：Dense FFN 是什么

Transformer 的 attention 负责“看谁”，FFN 负责“看完以后怎么变换”。Dense FFN 就像一个所有 token 都必须经过的专家组：参数完整，但每个 token 都支付完整计算成本。

x → Down(x) → 激活 → Up(x) → y

第二层：MoE 为什么有用

MoE 把一个巨大 FFN 拆成很多专家，并增加一个 router。router 根据 token 表示给专家打分，只让少数专家工作：

scores = Router(x)
chosen = TopK(scores)
y = Σ weight_i · Expert_i(x)

这样可以拥有很多“总参数”，但每个 token 只激活一小部分参数。它不是让所有专家同时投票，而是让 router 做稀疏选择。

LatentMoE：专家先在窄空间工作

普通 MoE 的 routed expert 通常接收完整宽度的 x。LatentMoE 先用 W_down 把表示压到更窄的 latent 空间，再让专家处理，最后用 W_up 还原：

x (宽度 d)
  ├─ shared experts: 直接处理宽度 d
  └─ routed experts: W_down → latent 宽度 l → 专家 → W_up
合并两条路径

Kimi K3 的公开配置是隐藏宽度 7168、latent MoE 宽度 3584、896 个 routed experts、每 token 选择 16 个、2 个 shared experts。这里的“latent”首先表示更窄的中间表示空间，不要把它理解成另一个模型或一个缓存文件。

一句话：LatentMoE 不是“把专家变成 latent”，而是“让路由专家在 latent 宽度上工作，降低极端稀疏 MoE 的通信和参数流量”。

第三层：普通 Attention 在缓存什么

普通 causal attention 的当前 token 会用 query q_t 访问所有历史的 key/value：

o_t = softmax(q_t K_≤tᵀ) V_≤t

因此推理时要保存每个历史 token 的 K/V。序列越长，缓存越长；但它的优点是当前 token 可以直接访问任意历史位置。

第四层：KDA 换了什么

KDA 不把全部历史 K/V 原样保留，而是维护一个递归状态 S_t。新 token 到来时，旧信息先按 forget gate 衰减，再写入当前 token 的信息：

S_t = decay(S_{t-1}) + write(k_t, v_t)
o_t = S_tᵀ q_t

你可以把它想成一本不断更新的摘要笔记：每一步都能继续写，但不能像普通 Attention 一样随时翻回原始历史的每一行。好处是长序列的状态更新更紧凑；代价是它需要设计好 state 的语义和恢复位置。

为什么 K3 要混合 KDA 和 Gated MLA

KDA
便宜地持续混合长历史，维护递归 state。
KDA
继续更新 state，适合连续 decode。
KDA
重复线性路径，控制长上下文成本。
Gated MLA
用 latent cache 做全局内容访问。
LatentMoE
在 channel mixing 阶段稀疏扩大容量。

所以 K3 不是在 KDA 和普通 Attention 之间二选一，而是让 KDA 承担高频的长序列混合，让周期性 Gated MLA 保留全局检索能力。

把概念连到 KV Cache

KDA cache保存截至某个位置的递归 state；命中时要验证 state 版本、位置和 dtype。
MLA cache保存压缩 latent token/page；可以采用分页和 prefix sharing。
MoE cache通常不是 token KV 的主体；专家权重/路由元数据属于模型执行路径。
